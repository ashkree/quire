# Quire Build Plan (v1)

Build order for the v1 spec. Each task is sized for one agent session and one pull request.

**How to use this file**

- Work on the first unchecked task whose dependencies are all checked. Do one task per branch and per pull request.
- "Implements" lists the requirement IDs from `docs/SPEC.md` the task must satisfy. Read those sections before starting.
- "Done when" is the acceptance test. If you can't make it pass as written, stop and report why. Don't weaken the check.
- Tick the box in the same pull request that completes the task.

The order is deliberate: core and CLI first, MCP and agent next, GUI last. The three riskiest pieces (rendering, validation, agent invocation) are proven by the end of M5, before any GUI work.

---

## M0 — Scaffold

- [ ] **T0.1 Workspace.** Create the four crates from SPEC 4.1 with the dependency rule enforced (no forbidden edges). Add `rust-toolchain.toml` pinned to a stable release.
  - Implements: INV-6
  - Done when: `cargo build --workspace` passes; `cargo tree -p quire-core` shows no Dioxus, rmcp, or tokio process crates.
- [ ] **T0.2 Pin dependencies.** Add exact versions (`=x.y.z`) for dioxus (0.7 series), rmcp, typst-as-lib and the Typst crates it uses, sqlx (sqlite, runtime-tokio, migrate), serde, serde_json, toml, uuid (v7), thiserror, anyhow, tracing, directories, tokio. Record every version in `DECISIONS.md` D-016.
  - Done when: `Cargo.lock` is committed and D-016 lists every pinned crate.
- [ ] **T0.3 CI.** GitHub Actions on `ubuntu-latest` and `macos-latest`: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, with `SQLX_OFFLINE=true`.
  - Implements: NFR-4
  - Done when: CI is green on an empty-but-compiling workspace.
- [ ] **T0.4 Data directory.** `quire_core::paths` resolving data dir, config dir and `QUIRE_DATA_DIR` override.
  - Implements: ARCH-4, ARCH-5, ARCH-6, ARCH-7
  - Done when: unit tests cover the override and the default on the host OS.

## M1 — Vault

- [ ] **T1.1 Migration and connection.** `migrations/0001_init.sql` exactly as SPEC 5.2 and 5.3. Connection setup with the ARCH-1 pragmas. Refuse newer schemas.
  - Implements: ARCH-1, DB-3, DB-4, DB-5, DB-10, INV-8
  - Done when: tests prove that updating or deleting a final artifact fails, a second final per application fails, a second default template fails, and a database marked with an unknown future migration is refused.
- [ ] **T1.2 Models and repository.** Typed structs and CRUD for every vault table, with DB-1 ids and timestamps, DB-2 `updated_at`, DB-7 and DB-8 checks, and DB-9 slug normalisation. Commit `.sqlx/`.
  - Implements: DB-1, DB-2, DB-6, DB-7, DB-8, DB-9
  - Done when: each rule has a passing and a failing test.
- [ ] **T1.3 Seed default template.** Embed `assets/templates/default.typ` (a placeholder is fine until T2.3) and insert it as default on a fresh database.
  - Implements: DB-11
  - Done when: a fresh database has exactly one default template.
- [ ] **T1.4 TOML import and export.** Format from SPEC 6. Add `quire import` and `quire export`.
  - Implements: VAULT-1, VAULT-2, VAULT-3, VAULT-4, CLI-1
  - Done when: `tests/fixtures/vault/full.toml` round-trips unchanged, an invalid file changes nothing and reports each error's location, and VAULT-4 has a test.
- [ ] **T1.5 Vault snapshot.** `VaultSnapshot`: an in-memory, read-only copy of the non-archived vault, loaded in one transaction. Validation, resolve and MCP reads all use it.
  - Done when: a test shows that a write during a snapshot's lifetime does not change it.

## M2 — Renderer

- [ ] **T2.1 Fonts.** Choose and add fonts under `assets/fonts/` (open licences only, licence files included). Record the choice in D-017.
  - Implements: INV-7, RENDER-4
  - Done when: the embedded fonts render every character in `tests/fixtures/text/glyphs.txt` (Latin Extended, Greek, Cyrillic) with no missing-glyph warning.
- [ ] **T2.2 Resolve.** `resolve(&Selection, &VaultSnapshot) -> ResolvedCv` with JSON serialisation as SPEC 8.2.
  - Implements: RESOLVE-1 to RESOLVE-6
  - Done when: each RESOLVE rule has a test, and `tests/fixtures/resolved/full.json` is generated by resolve from fixture data, not written by hand.
- [ ] **T2.3 Default template.** `assets/templates/default.typ` reading `cv_json` as RENDER-2. Confirm the `json(bytes(...))` call works with the pinned Typst version and record it in D-018.
  - Implements: RENDER-2, RENDER-3, RENDER-8, RESOLVE-6
  - Done when: `full.json`, `minimal.json` (every optional field null) and `special-chars.json` all compile, and the last one renders `C# $2M R&D 50% *nix user@host a_b <tag> \` literally.
- [ ] **T2.4 Render API.** `render` and `render_preview` as RENDER-6 and RENDER-7, with fixed PDF timestamp and identifier.
  - Implements: RENDER-1, RENDER-5, RENDER-6, RENDER-7
  - Done when: rendering the same input twice gives the same bytes, and a golden SHA-256 per fixture is checked in CI on both operating systems.
- [ ] **T2.5 Reading-order test.** Extract text from each fixture PDF (dev dependency chosen here, record it) and compare with the resolved CV's text order.
  - Implements: RENDER-9
  - Done when: the test passes for all fixtures and fails if two sections are swapped in the template.
- [ ] **T2.6 `quire render`.** CLI from SPEC 11.
  - Done when: rendering a fixture selection writes a PDF and prints the page count.

## M3 — Validation and drafts

- [ ] **T3.1 Selection type and schema.** `Selection` struct, embedded `selection.schema.json` from SPEC 7.1, and a test that the struct and the schema agree.
  - Implements: VAL-1
  - Done when: a schema-valid fixture deserialises, and an extra field is rejected.
- [ ] **T3.2 Validation.** `validate` as SPEC 7.2. Messages written for an agent to act on.
  - Implements: VAL-2 to VAL-5, VAL-7
  - Done when: every rule has a passing and a failing test, and VAL-5 has property tests (random selections never pass a number absent from the vault without a warning).
- [ ] **T3.3 Draft pipeline.** One function used by both MCP and agent runs: validate, resolve, render, VAL-6, insert draft with the next version, in one transaction. Includes the MCP-10 duplicate check.
  - Implements: VAL-6, MCP-9, MCP-10, INV-2
  - Done when: a render error inserts nothing; an identical resubmission returns the existing draft.
- [ ] **T3.4 Finalise and export.** `quire finalise` and `quire artifact export`, with the export copy from SET-1 and SET-2.
  - Implements: INV-1, INV-5, SET-1, SET-2
  - Done when: finalising twice fails cleanly; a failed copy leaves the artifact final; file names with `/` and `:` are sanitised.

## M5 — Orchestration

- [ ] **T5.1 Applications CLI.** `quire app add` (paste via `--jd-file` only for now) and `quire app list`.
  - Implements: INTAKE-1, INTAKE-5, INTAKE-6, CLI-2
  - Done when: tests cover truncation and duplicate-URL warnings.
- [ ] **T5.2 Settings.** `settings.toml` load and save with defaults and unknown-key preservation.
  - Implements: SET section 14
  - Done when: a round-trip test keeps unknown keys.
- [ ] **T5.3 Runner trait and fake runner.** `AgentRunner` as SPEC 10.1, and a fake agent binary in tests that can succeed, hang, crash, return malformed JSON, or return no `structured_output`.
  - Done when: the fake covers each case, used by T5.4 tests.
- [ ] **T5.4 Claude runner.** As SPEC 10.2. Verify flags against `claude --help` and record the version in D-019.
  - Implements: AGENT-1 to AGENT-11
  - Done when: every fake-runner case produces the correct `agent_runs` state, cancellation kills the process group, and one manual run against real Claude produces a valid draft (logged in `docs/manual-tests.md`).
- [ ] **T5.5 `quire generate` and `quire doctor`.**
  - Done when: `generate` goes from application to draft PDF from the terminal, and `doctor` reports a missing `claude` clearly.

**Checkpoint.** After M5, use the CLI for real applications before starting the GUI. Write down what was missing in `docs/feedback.md`.
